## Story

As a Developer,
I want to have a robust database schema for Products and Vendors populated with realistic B2B data,
so that I can build the frontend components against a stable data structure.

## Acceptance Criteria

1. **Database Schema Creation**
   - **Given** a PostgreSQL database is provisioned (Prisma 7 / PostgreSQL 18).
   - **When** I run the `prisma migrate dev` command.
   - **Then** the `Vendor` table is created with:
     - `id` (UUID or CUID)
     - `name` (String)
     - `slug` (String, unique)
     - `logoUrl` (String, optional)
   - **And** the `Product` table is created with:
     - `id` (UUID or CUID)
     - `name` (String)
     - `description` (String/Text)
     - `priceHt` (Int, in cents)
     - `stock` (Int)
     - `sku` (String, unique)
     - `category` (String/Enum)
     - `vendorId` (Foreign Key)
   - **And** the relationship is correctly enforced (Product belongs to Vendor).

2. **Seeding Data**
   - **When** I run the `prisma db seed` command.
   - **Then** at least **5 Vendors** are created.
   - **And** at least **50 Products** are created and linked to vendors.
   - **And** prices are stored as **integers** (e.g., 1000 for 10.00€).
   - **And** product categories include "Textile", "Beauty", "Food" (as per business context).

## Dev Notes

- **Technical Stack:** Prisma 7, PostgreSQL 18.
- **Strict Typing:** Ensure generated Prisma types are used. Do not manually redefine types if `Prisma.ProductGetPayload` or similar can be used.
- **Pricing:** CRITICAL. Store all prices in **cents** (integer). `priceHt = 1050` means 10.50.
- **Multi-tenancy:** The `vendor_id` is the foundation of multi-tenancy. Ensure it is non-nullable on Products.
- **File Locations:**
  - Schema: `prisma/schema.prisma`
  - Seed: `prisma/seed.ts`
  - Lib: `src/lib/prisma.ts` (Ensure singleton pattern is used for Next.js hot-reloading).

### Project Structure Notes

- **Prisma Client:** Should be instantiated in `src/lib/prisma.ts` to prevent "too many connections" errors during HMR in Next.js.
- **Environment:** Ensure `.env` is configured (or `.env.local` instructions provided) for `DATABASE_URL`.
